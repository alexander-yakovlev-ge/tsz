# Сайт ТСЖ — Тамар Мепе, 1 (Батуми)

Веб-приложение товарищества собственников жилья: публичный сайт, личный кабинет собственников и админ-панель.

- Техническое задание — [docs/requirements.md](docs/requirements.md)
- План работ и процедура приёмки этапов — [docs/plan.md](docs/plan.md)
- Результаты приёмки — [docs/acceptance/](docs/acceptance/)

## Быстрый старт

Нужны только Docker и Docker Compose.

```sh
make up       # создаёт .env из .env.example, собирает образы, ждёт готовности всех сервисов
```

Сайт открывается по адресу https://localhost. Сертификат выпускает локальный CA Caddy. Чтобы браузер ему доверял, выполните `make cert` и добавьте `caddy-root.crt` в доверенные корневые сертификаты.

Первый администратор создаётся автоматически из `ADMIN_PHONE` / `ADMIN_PASSWORD` в `.env`. Вход — `https://localhost/ru/login` (телефон можно вводить без кода страны).

В `.env` обязателен `JWT_SECRET` — секрет подписи сессии, не короче 32 символов (`openssl rand -base64 48`). `ENABLE_TEST_API=true` включает тестовый API для e2e; на сервере — `false`. `SITE_URL` — публичный адрес сайта для canonical, hreflang и `sitemap.xml`.

С этапа 4 обязателен `ID_NUMBERS_KEY` — ключ шифрования номеров документов собственников, не короче 32 символов. Если `.env` создан раньше, добавьте его вручную: `echo "ID_NUMBERS_KEY=$(openssl rand -base64 48)" >> .env`. После загрузки реальных данных ключ менять нельзя (номера станут нечитаемыми) — храните его вместе с резервными копиями.

Помещения и собственники загружаются в админке, раздел «Импорт» (`/ru/admin/import`). Выписка загружается одним файлом `registry.csv`: строка — помещение и один его собственник. Синтетическая выписка для проверки — `make fixtures`, файл `data/fixtures/registry.csv`.

## Команды

| Команда                 | Что делает                                           |
| ----------------------- | ---------------------------------------------------- |
| `make up`               | Собрать и запустить стек, дождаться healthy          |
| `make down`             | Остановить (данные сохраняются)                      |
| `make reset`            | Удалить контейнеры и **все данные**                  |
| `make restart`          | Перезапустить сервисы                                |
| `make ps` / `make logs` | Состояние / логи                                     |
| `make check`            | Prettier, ESLint, typecheck                          |
| `make test`             | Модульные и интеграционные тесты                     |
| `make e2e`              | E2E-тесты Playwright против развёрнутого стека       |
| `make smoke`            | Smoke-проверка развёрнутого стека                    |
| `make fixtures`         | Синтетические тестовые данные в `data/fixtures`      |
| `make psql`             | Консоль PostgreSQL                                   |
| `make dev`              | Режим разработки с hot reload                        |
| `make accept`           | **Полная приёмка этапа с нуля** (plan.md, разд. 1.1) |

Все проверки выполняются в контейнерах, Node.js на машине не нужен.

## Сервисы

| Сервис     | Назначение                                                          | Доступ снаружи               |
| ---------- | ------------------------------------------------------------------- | ---------------------------- |
| `proxy`    | Caddy: HTTPS, `/api/*` → api, `/files/*` → storage, остальное → web | `:80`, `:443`                |
| `web`      | Next.js 15 (страницы, SSR)                                          | через proxy                  |
| `api`      | NestJS 11 (REST API); при старте — миграции и seed                  | через proxy (`/api`)         |
| `worker`   | Фоновые задачи (pg-boss)                                            | —                            |
| `postgres` | PostgreSQL 17                                                       | — (`make psql`)              |
| `storage`  | SeaweedFS — S3-совместимое хранилище файлов                         | filer UI на `127.0.0.1:8888` |

## Структура

```
apps/api         NestJS: API, Prisma-схема и миграции, seed, воркер (src/worker.ts)
apps/web         Next.js
packages/shared  Общие типы и утилиты фронтенда и бэкенда
tools/fixtures   Генератор синтетических тестовых данных
e2e              Playwright
infra            Конфигурация Caddy, точки входа контейнеров
```

## Разработка без Docker

Возможна для отдельных пакетов (нужны Node.js 22 и pnpm 10):

```sh
pnpm install
pnpm check
pnpm test
```

Проект использует публичный реестр npm (`.npmrc`), даже если глобально настроен другой.
