## 1. Общее описание

Веб-приложение для управления ТСЖ (товарищество собственников жилья). Состоит из трёх частей:
- публичная часть для всех посетителей;
- личный кабинет собственников;
- административная панель для управляющих.

Объём по выписке из Публичного реестра от 08.10.2026: 259 квартир, 47 машиномест, 5 коммерческих и 1 техническое помещение — всего 312. Нагрузка небольшая.

### 2.1 Структура репозитория
Монорепозиторий на pnpm workspaces:
```
apps/web       — Next.js (страницы, SSR)
apps/api       — NestJS (REST API, авторизация, бизнес-логика)
apps/worker    — точка входа воркера (использует модули apps/api)
packages/shared — Zod-схемы, типы DTO, enum'ы, общие утилиты (деньги, телефоны, периоды)
```

### 2.2 Окружение и маршрутизация
- Перед сервисами стоит reverse-proxy (Caddy). Он работает на одном домене:
  - `/api/*` → `api`;
  - всё остальное → `web`.
- Благодаря одному домену cookie сессии доступна и фронтенду, и API.
- Next.js на сервере обращается к API по внутреннему адресу (`http://api:3001`) и пробрасывает cookie пользователя.
- Сервисы Docker Compose: `proxy`, `web`, `api`, `worker`, `postgres`, `minio`, `backup`.
- **Локальный запуск.** Весь стек поднимается командой `docker compose up` на машине разработчика. Seed выполняется автоматически.
- Продакшен использует тот же compose-файл с отдельным `.env`. Сервер и домен приобретаются после тестирования в локальных контейнерах.
- Push работает на `localhost` без HTTPS. Для проверки на iOS и других устройствах в сети нужен HTTPS: локальный сертификат Caddy или туннель.

### 3.2 Требования
- Переключатель языка находится в шапке сайта и доступен на всех страницах.
- Язык хранится в URL-префиксе: /ka/..., /ru/..., /en/...
- При первом заходе определяется язык браузера. Если он не поддерживается, используется грузинский.
- Все строки интерфейса переведены на три языка: сообщения об ошибках, тексты push-уведомлений и SMS.
- Пользовательский контент хранится в БД в трёх вариантах (`*_ka`, `*_ru`, `*_en`). **Все три перевода обязательны** — форма без них не сохраняется.

## 4. База данных: модели

> Частичные уникальные индексы (`... WHERE ...`) Prisma не поддерживает. Они создаются SQL-миграцией вручную.
>
> Все даты и границы месяцев считаются в часовом поясе `Asia/Tbilisi`. Деньги хранятся как `Decimal(10,2)`, валюта — GEL.

### 4.1 User — пользователь системы
```
id                     UUID, PK
phone                  String               — логин в формате E.164; UNIQUE (phone) WHERE deleted_at IS NULL
password_hash          String
role                   Enum: ADMIN | RESIDENT
name                   String (nullable)    — имя учётной записи (для администраторов без собственности; у собственников имя берётся из Owner)
language               Enum: ka | ru | en   — язык уведомлений, по умолчанию ka
notify_announcements   Boolean, default true — push о новых объявлениях
notify_balance         Boolean, default true — push об операциях по балансу
token_version          Int, default 0       — увеличивается при смене роли, смене/сбросе пароля, удалении; токен с устаревшей версией отклоняется
announcements_seen_at  DateTime (nullable)  — когда пользователь последний раз открывал список объявлений (для бейджа)
deleted_at             DateTime (nullable)  — мягкое удаление
created_at             DateTime
```

### 4.2 Unit — помещение
```
id                 UUID, PK
kind               Enum: APARTMENT | PARKING | COMMERCIAL | TECHNICAL
cadastral_code     String, UNIQUE       — кадастровый код из выписки, например 05.30.39.005.01.01.045; ключ импорта и синхронизации
number             String               — номер как в реестре: «45», «5ა», «228»; для машиноместа — «12»
sort_key           String               — ключ натуральной сортировки (вид + число + суффикс)
floor              Int (nullable)       — -3 для паркинга
floor_label        String (nullable)    — нестандартный этаж, например «тех. этаж (отм. 65.10)»
area_m2            Decimal(8,2)         — площадь по выписке (справочно, на начисления не влияет)
tariff_category    Enum TariffCategory: FULL | BLACK_FRAME | PENSIONER (nullable) — обязательна для APARTMENT, NULL для остальных
balance            Decimal(10,2)        — > 0 переплата (аванс), < 0 задолженность
status             Enum: ACTIVE | MERGED
merged_into_id     UUID → Unit (nullable) — куда объединено помещение (при status = MERGED)
created_at         DateTime
updated_at         DateTime
```
> Помещение соответствует юридической единице по выписке из Публичного реестра: **одно помещение — одно ежемесячное начисление (если для вида задана ставка) и один голос**. Объединённая квартира — одно помещение. В реестре объединение отражается либо новым кадастровым кодом (квартира N228 = код 502), либо сохранением старого (квартира N132).
>
> Номер может содержать грузинскую букву (5ა, 5ბ, 5გ, 5დ). Для отображения на ru/en используется транслитерация: 5а / 5a.

| Вид | Кол-во | Начисление | Голос | Платные услуги |
|---|---|---|---|---|
| APARTMENT | 259 | по категории тарифа | да | да |
| PARKING | 47 | единая ставка без льгот | да | нет |
| COMMERCIAL | 5 | нет (ставка в тарифе не задана) | да | нет |
| TECHNICAL | 1 | нет (ставка в тарифе не задана) | да | нет |

### 4.3 Owner — собственник по реестру
```
id              UUID, PK
kind            Enum: PERSON | COMPANY
registry_name   String               — имя или название как в выписке (грузинским письмом)
display_name    String (nullable)    — имя для интерфейса (латиница/кириллица); вносит администратор или сам собственник
id_numbers      String[]             — личный номер, номера документов, ID компании; нормализованы (без пробелов и дефисов, верхний регистр)
user_id         UUID → User (nullable) — учётная запись, через которую собственник пользуется сайтом
note            String (nullable)    — служебная заметка администратора
created_at      DateTime
updated_at      DateTime
```
- Собственник существует **независимо от учётной записи**: начисления и голос принадлежат помещению, а сайт доступен, только когда к собственнику привязана учётная запись.
- У физлица `user_id` — его собственная учётная запись. У юрлица — учётная запись представителя.
- Одна учётная запись может быть привязана к нескольким собственникам. Например, представитель компании, который сам тоже собственник.
- `id_numbers` видны **только администраторам** и используются для сопоставления при синхронизации с выпиской (п. 8.10). В API для жильцов и в экспорт не попадают.
- В интерфейсе показывается `display_name`, а если его нет — `registry_name`.

### 4.3.1 UnitOwnership — право собственности на помещение
```
id          UUID, PK
unit_id     UUID → Unit
owner_id    UUID → Owner
share_num   Int (nullable)         — числитель доли (NULL — без указания долей)
share_den   Int (nullable)         — знаменатель доли
share_note  String (nullable)      — сложные случаи, например «1/4 совместно с …»
is_contact  Boolean, default false — основное контактное лицо по помещению
UNIQUE (unit_id, owner_id)
```

> **Термины.** Далее в ТЗ:
> - «собственники помещения» — записи `Owner`, связанные с помещением через `UnitOwnership`;
> - «пользователи помещения» — учётные записи `User`, привязанные к этим собственникам. Через них определяется доступ в личный кабинет, к документам помещения и получатели push.

### 4.4 Tariff — тариф ежемесячного платежа
```
id                  UUID, PK
name                String (nullable)  — необязательное название
amount_full         Decimal(10,2)      — квартира, категория FULL
amount_black_frame  Decimal(10,2)      — квартира, категория BLACK_FRAME
amount_pensioner    Decimal(10,2)      — квартира, категория PENSIONER
amount_parking      Decimal(10,2)      — машиноместо
amount_commercial   Decimal(10,2) (nullable) — коммерческое помещение; NULL — не начислять
amount_technical    Decimal(10,2) (nullable) — техническое помещение; NULL — не начислять
effective_from      Date               — с какой даты действует
created_by          UUID → User (Admin)
created_at          DateTime
```
> **Действующий тариф на дату D** — запись с максимальным `effective_from ≤ D`.
>
> Сейчас коммерческие и технические помещения не начисляются: их ставки пустые. Если это изменится, достаточно задать ставку в новом тарифе — код менять не нужно.
>
> **Сумма ежемесячного начисления** = ставка по виду и категории помещения из тарифа, действующего на первое число периода. Ставка фиксированная, от площади не зависит. Помещения, для вида которых ставка пустая, пропускаются.

### 4.5 BalanceTransaction — операция по балансу
```
id              UUID, PK
unit_id         UUID → Unit
amount          Decimal(10,2)      — изменение баланса: > 0 увеличивает, < 0 уменьшает
type            Enum: MONTHLY_CHARGE | SERVICE_DEBIT | PAYMENT | OPENING_BALANCE | MERGE_TRANSFER | CUSTOM
period          Date (nullable)    — первое число месяца; обязателен для MONTHLY_CHARGE
service_id      UUID → PaidService (nullable, ON DELETE RESTRICT; при type = SERVICE_DEBIT)
tariff_id       UUID → Tariff (nullable; при type = MONTHLY_CHARGE)
related_unit_id UUID → Unit (nullable; при type = MERGE_TRANSFER — второе помещение)
comment         String (nullable)
created_by      UUID → User (nullable — NULL для автоматических начислений)
created_at      DateTime

UNIQUE (unit_id, period) WHERE type = 'MONTHLY_CHARGE'
UNIQUE (unit_id) WHERE type = 'OPENING_BALANCE'
```

| Тип | Знак `amount` | Смысл |
|-----|---------------|-------|
| MONTHLY_CHARGE | < 0 | Ежемесячный взнос за период по тарифу |
| SERVICE_DEBIT | < 0 | Платная услуга по цене для категории помещения |
| PAYMENT | > 0 | Поступление денег от собственника |
| OPENING_BALANCE | любой, ≠ 0 | Входящий остаток на момент запуска. Не больше одной на помещение. Комментарий и хотя бы один документ обязательны |
| MERGE_TRANSFER | любой | Перенос баланса при объединении помещений (парные операции) |
| CUSTOM | любой, ≠ 0 | Корректировка или сторно ошибочной операции; комментарий обязателен |

Правила:
- Транзакции **неизменяемы**: их нельзя ни редактировать, ни удалять. Ошибку исправляют операцией CUSTOM с комментарием.
- Транзакция создаётся в одной БД-транзакции с изменением `Unit.balance` (атомарный `UPDATE ... SET balance = balance + :amount`).
- `Unit.balance` всегда равен сумме `amount` всех транзакций помещения. Сверка — п. 8.9.
- После фиксации операции владельцам помещения ставится в очередь push об изменении баланса (п. 7.5).

### 4.9 Document — документ
```
id                 UUID, PK
title_ka           String
title_ru           String
title_en           String
category_id        UUID → DocumentCategory
visibility         Enum: PUBLIC | OWNERS | PRIVATE
storage_key        String               — ключ объекта в MinIO
original_filename  String
file_size          Int
mime_type          String

```

| visibility | Кто видит и скачивает |
|---|---|
| PUBLIC | Все посетители |

## 5. Аутентификация и авторизация

### 5.1 Вход
- Форма: номер телефона + пароль.
- Телефон нормализуется в E.164 (`libphonenumber-js`). Принимаются любые международные номера. Номер без кода страны считается грузинским: `555 12 34 56` → `+995555123456`.
- При неуспешном входе показывается общее сообщение «Неверный телефон или пароль».
- Удалённые пользователи войти не могут.
- Rate limiting: не более 10 попыток входа за 15 минут с одного IP.

### 5.2 Регистрация
- Пользователей создаёт администратор: вручную или CSV-импортом.
- Пользователь получает первоначальный пароль от администратора. Сменить его можно в личном кабинете.

### 5.3 Смена пароля
- Форма в личном кабинете: текущий пароль + новый пароль + подтверждение.
- Минимальная длина — 8 символов.
- После смены увеличивается `token_version`, и сессии на других устройствах завершаются.

### 5.4 Роли
| Роль | Права |
|------|-------|
| ADMIN | Полный доступ ко всем разделам и операциям. Если привязан к помещениям — также личный кабинет |
| RESIDENT | Публичные страницы, документы «для собственников», личный кабинет |

### 5.5 Сессии
- Бэкенд выдаёт JWT в cookie `session`:
  - атрибуты `httpOnly`, `Secure`, `SameSite=Lax`;
  - срок жизни 24 часа.
- Скользящее продление: если до истечения осталось меньше 12 часов, при любом запросе бэкенд выдаёт новую cookie.
- В токене хранятся `user_id`, `role`, `token_version`. При каждом запросе к API версия сверяется с БД, поэтому смена роли, сброс пароля и удаление действуют сразу.

### 5.6 Восстановление пароля по SMS
1. На странице входа ссылка «Забыли пароль?» ведёт к форме ввода телефона.
2. Ответ всегда одинаковый: «Если номер зарегистрирован, вам придёт SMS с кодом». Так нельзя проверить, зарегистрирован ли номер.
3. На номер отправляется 6-значный код. Текст SMS — на языке пользователя. Код действует 10 минут.
4. Пользователь вводит код и новый пароль (минимум 8 символов). После этого:
   - увеличивается `token_version`;
   - все сессии завершаются;
   - код помечается использованным.

Ограничения:
- не больше 3 запросов кода в час на номер и 10 в час с IP;
- не больше 5 попыток ввода на один код.

К запуску не требуется (этап 6). Пока SMS-провайдер не подключён, ссылка «Забыли пароль?» скрыта и пароль сбрасывает администратор (п. 8.2).

## 6. Публичная часть сайта

### 6.1 Страница «Объявления» (/announcements)

- Для каждого объявления: заголовок, дата публикации, превью с кнопкой «Читать далее».

- Доступна без авторизации.

### 6.2 Главная страница (/)
- Название ТСЖ, адрес и приветствие из `HomePage` на активном языке.

- Документы показываются по категориям в порядке `sort_order`.

  - гость видит PUBLIC;
  - собственник — PUBLIC и OWNERS;
  - администратор — все.

- Поиск по названию (фронтенд-фильтр).
- Страница рендерится динамически, без ISR, потому что содержимое зависит от пользователя.

### 6.4 Страница «Услуги» (/services)
- Список активных услуг: название, описание, цены по трём категориям: Полный / Черный каркас / Пенсионер.

- Редактирование — только в админке (/admin/services).

### 6.5 Страница «Контакты» (/contacts)
- Телефон председателя с именем.
- Телефон ответственного за связь с собственниками с именем.
- Ссылка на Telegram-канал (открывается в новой вкладке).
- Доступна без авторизации.

## 7. Личный кабинет (/account)

Доступен авторизованным пользователям (RESIDENT и ADMIN), привязанным к собственнику хотя бы одного помещения. Видны все помещения всех собственников, к которым привязана учётная запись. Пользователь без помещений видит сообщение «К вашему аккаунту не привязано ни одно помещение».

### 7.1 Выбор помещения
- Если помещение одно, сразу показывается его информация.
- Если помещений несколько (например, квартира и машиноместо), они переключаются вкладками или выпадающим списком. Подпись: «Квартира 45», «Машиноместо 12», «Коммерческое помещение 3».
- Для представителя компании помещения сгруппированы по собственнику.
- Отображаются собственники помещения (имя и доля, если указана). Телефоны других пользователей не показываются: жилец видит только свой номер.
- Пользователь может указать своё отображаемое имя (`Owner.display_name`) — это удобно, потому что в реестре имя записано по-грузински.

### 7.2 Баланс
- Текущий баланс в GEL.
- Цветовая индикация и подпись:
  - зелёный «Переплата» — баланс > 0;
  - красный «Задолженность» — баланс < 0;
  - серый — баланс 0.
- Для квартиры — категория тарифа. Также кадастровый код и площадь.
- Документы помещения (выписки из реестра) — для скачивания.

### 7.3 История операций
- Таблица операций: дата, тип, период (для ежемесячных начислений), сумма, комментарий, приложенные документы (ссылки на скачивание).
- Пагинация по 20 записей, новые первыми.

### 7.4 Смена пароля
- См. п. 5.3. Отдельная страница `/account/change-password`.

### 7.5 Уведомления (/account/notifications)
- Переключатель «Получать уведомления на этом устройстве».
  - При включении запрашивается разрешение браузера (только по нажатию пользователя), подписка сохраняется на сервере.
  - При выключении подписка удаляется.
- Список устройств с подпиской и кнопкой «Отключить» для каждого.
- Настройки:
  - «Новые объявления» (`notify_announcements`);
  - «Операции по балансу» (`notify_balance`): начисления, оплаты, списания за услуги, корректировки;
  - язык уведомлений (`language`).
- Для iOS выводится подсказка: уведомления работают только после установки сайта на экран «Домой» (iOS 16.4+).
- Перед выходом из аккаунта клиент удаляет подписку текущего устройства.

**Текст push об операции** (шаблон i18n на языке пользователя):
- заголовок: «{Помещение}: {тип операции}»;
- текст: «{±сумма} GEL{, период}. Баланс: {баланс} GEL»;
- нажатие открывает историю операций помещения.

## 8. Административная панель (/admin)

Доступна только пользователям с ролью ADMIN.

### 8.0 Дашборд (/admin)

### 8.1 Раздел «Помещения» (/admin/units)

#### Список помещений
Пагинация по 50 записей. Столбцы:
- Номер и вид помещения
- Собственники: имя, доля; телефоны привязанных учётных записей. Если ни к одному собственнику не привязана учётная запись — пометка «нет контакта». Администратор видит все контактные данные.
- Категория тарифа (для квартир)
- Текущий баланс
- Действия

#### Действия по помещению
| Кнопка | Действие |
|--------|----------|
| −Ежемесячный | Ручное начисление за выбранный период. Используется для помещений, добавленных после автоначисления, и для догоняющих начислений. Сумма считается по п. 4.4. Если за период начисление уже есть — отказ с сообщением |
| −Услуга | Только для квартир. Выбор услуги из списка, стоимость подставляется по категории квартиры (тип SERVICE_DEBIT) |
| +Оплата | Сумма (> 0), комментарий, необязательные документы. Тип PAYMENT |
| Входящий остаток | Сумма (любой знак), обязательный комментарий и хотя бы один документ. Тип OPENING_BALANCE. Доступно, пока у помещения нет такой операции |
| Корректировка | Произвольная сумма (знак определяет направление), обязательный комментарий, необязательные документы. Тип CUSTOM |

#### Фильтры и поиск
- Поиск по номеру помещения, кадастровому коду, телефону или имени собственника (в реестровом и отображаемом написании).
- Фильтры: вид помещения, категория тарифа, только должники, «нет контакта».
- Сортировка по номеру (`sort_key`) и по балансу.

#### Добавление / редактирование помещения
Форма:
- Вид (квартира / машиноместо / коммерческое / техническое)
- Кадастровый код (обязательно, уникален)
- Номер
- Этаж или подпись этажа (необязательно)
- Площадь, м²
- Категория тарифа (обязательна для квартир)
- Документы помещения: выписки из реестра и другие (п. 4.19)
- При создании — флажок «Начислить за текущий месяц». Показывается, если автоначисление за текущий месяц уже прошло, по умолчанию включён
- Собственники: поиск собственника (п. 8.12) по имени или номеру документа, «Добавить», «Отвязать», доля, отметка контактного лица

#### Удаление помещения
- Только если по помещению нет операций. Иначе помещение остаётся в истории; при необходимости его можно объединить с другим.

#### Объединение квартир
Квартиры объединяются официально.
1. Администратор выбирает основное помещение и одно или несколько присоединяемых.
2. Указывает номер и кадастровый код объединённого помещения по выписке (новый код, если реестр его присвоил), категорию и площадь. Прикладывает выписку из Публичного реестра, подтверждающую объединение: она обязательна и сохраняется как документ основного помещения.
3. В одной БД-транзакции:
   - баланс каждого присоединяемого помещения переносится на основное парой операций MERGE_TRANSFER: на присоединяемом остаток обнуляется, на основном увеличивается или уменьшается на ту же сумму;
   - собственники присоединяемых помещений привязываются к основному (без дублей);
   - присоединяемые помещения получают `status = MERGED` и `merged_into_id`.
4. Помещения со статусом MERGED не участвуют в начислениях и не показываются в списке по умолчанию (есть фильтр «Объединённые»). Их история операций сохраняется.

Объединённое помещение юридически одно: одно ежемесячное начисление и один голос. Если объединение выполнено после начисления за текущий месяц, администратор при необходимости корректирует начисления этого месяца вручную.

Операция пишется в AuditLog. Разъединение не предусмотрено. При ошибке объединение исправляется вручную корректировками.

### 8.2 Раздел «Пользователи» (/admin/users)
- Список: телефон, имя, роль, язык, привязанные собственники и их помещения, наличие push-подписки.
- Создание: телефон, имя, язык, временный пароль, роль, привязка к собственникам. Обычно учётная запись создаётся из карточки собственника (п. 8.12) или импортом контактов (п. 8.10).
- Редактирование: имя, телефон, язык, роль, привязанные собственники, сброс пароля. Смена роли и сброс пароля увеличивают `token_version`.
- При сбросе пароля администратор задаёт временный пароль вручную или генерирует его. Пароль показывается один раз.
- Удаление мягкое (`deleted_at`). Вместе с ним:
  - удаляются push-подписки;
  - увеличивается `token_version`;
  - учётная запись отвязывается от собственников (`Owner.user_id = NULL`). Собственники и их права на помещения сохраняются.

  Телефон удалённого пользователя можно использовать повторно.

### 8.3 Раздел «Тарифы и начисления» (/admin/billing)

#### Настройка тарифа
Форма:
- Сумма для квартир категории FULL (GEL)
- Сумма для квартир категории BLACK_FRAME (GEL)
- Сумма для квартир категории PENSIONER (GEL)
- Сумма для машиноместа (GEL)
- Сумма для коммерческого помещения (GEL, необязательно — пусто значит не начислять)
- Сумма для технического помещения (GEL, необязательно — пусто значит не начислять)
- Дата вступления в силу
- Название (необязательно)

После сохранения создаётся новая запись Tariff. Ниже формы — история тарифов.

#### Автоматическое начисление
- Задача по расписанию `pg-boss` запускается 1-го числа каждого месяца в 00:10 (Asia/Tbilisi) и начисляет за текущий месяц.
- Начисление получают все помещения со статусом ACTIVE, для вида которых в тарифе задана ставка. Сумма считается по тарифу, действующему на 1-е число (п. 4.4).
- Всё выполняется в одной БД-транзакции. Помещения, у которых начисление за период уже есть, пропускаются — уникальный индекс гарантирует отсутствие дублей.
- После выполнения:
  - результат пишется в AuditLog (`user_id = NULL`);
  - результат показывается на дашборде;
  - пользователям помещений уходят push об операции (п. 7.5).
- Если действующего тарифа нет, начисление не выполняется. На дашборде появляется предупреждение, администраторам с подпиской уходит push.
- **Помещения, добавленные после автоначисления**, получают начисление за текущий месяц полной суммой при создании (флажок в форме, п. 8.1). При необходимости администратор исправляет сумму корректировкой.

#### Ручной запуск
- Выбор периода и кнопка «Начислить всем за [месяц/год]». Используется, если автоначисление не прошло, или для прошлых периодов.
- Логика та же, что у автоматического. После выполнения показывается отчёт: обработано, пропущено (со списком), общая сумма.

### 8.10 Раздел «Импорт и синхронизация» (/admin/import)

Источник данных о помещениях и собственниках — выписка из Публичного реестра. ТСЖ переводит её в CSV (UTF-8, разделитель `;` или `,`); автоматический разбор PDF не предусмотрен. CSV с персональными данными в репозиторий не кладутся.

Импорт выполняется в три шага, каждый со своим файлом.

#### Шаг 1. Помещения — `units.csv`
| Столбец | Обязательный | Пример |
|---|---|---|
| cadastral_code | да | `05.30.39.005.01.01.045` |
| kind | да | `APARTMENT` / `PARKING` / `COMMERCIAL` / `TECHNICAL` |
| number | да | `45`, `5ა`, `12` |
| floor | нет | `7`, `-3` |
| floor_label | нет | `тех. этаж (отм. 65.10)` |
| area_m2 | да | `38.61` |
| tariff_category | для квартир | `FULL` / `BLACK_FRAME` / `PENSIONER` |

#### Шаг 2. Собственники — `owners.csv`
Одна строка — одна пара «помещение + собственник».

| Столбец | Обязательный | Пример |
|---|---|---|
| cadastral_code | да | код помещения из шага 1 |
| owner_key | да | метка собственника внутри файла — одинаковая во всех строках одного лица |
| owner_kind | да | `PERSON` / `COMPANY` |
| registry_name | да | имя или название как в выписке |
| id_numbers | нет | номера через `\|`, например `01001001001\|AB1234567` |
| share | нет | `1/2`, `50%` |
| share_note | нет | текст для сложных случаев |
| is_contact | нет | `1` / `0` |

Собственник сопоставляется с уже существующими в системе так:
1. по совпадению любого нормализованного номера из `id_numbers`;
2. иначе по точному совпадению `registry_name`.

**Неоднозначные совпадения не импортируются**, пока администратор не решит их вручную в предпросмотре. Это, например, однофамильцы или одно лицо с разными номерами.

#### Шаг 3. Контакты — `contacts.csv` (после запуска)
| Столбец | Обязательный | Пример |
|---|---|---|
| cadastral_code или owner_key | да | чтобы найти собственника |
| registry_name | если у помещения несколько собственников | для выбора нужного |
| phone | да | `+995555123456` или `555123456` |
| display_name | нет | `Иван Петров` |
| language | нет (по умолч. `ka`) | `ka` / `ru` / `en` |

- Для каждого телефона создаётся учётная запись RESIDENT (существующая находится по телефону) и привязывается к собственнику.
- Временные пароли выдаются одноразовым файлом для скачивания: телефон, имя, помещения, временный пароль. Пароли в открытом виде больше нигде не хранятся.
- Контакты по помещениям юрлиц (представители) загружаются тем же файлом.

#### Общие правила
- Каждый шаг: загрузка файла → предпросмотр с результатом проверки каждой строки → подтверждение. Пока есть ошибки, импорт не запускается.
- Импорт выполняется в одной транзакции и пишется в AuditLog.
- Повторная загрузка того же файла не создаёт дублей.
- Стартовый баланс помещений — 0. Начисление за текущий месяц при импорте не выполняется. Если импорт идёт после автоначисления, текущий месяц начисляется кнопкой «Начислить всем» — уже начисленные помещения она пропустит.
- Входящие остатки вносятся после импорта по каждому помещению операцией «Входящий остаток» с документами (п. 8.1).

#### Синхронизация с новой выпиской (периодически)
1. ТСЖ получает свежую выписку и готовит `units.csv` и `owners.csv` в том же формате.
2. Система сравнивает файлы с текущими данными и показывает разницу:
   - новые помещения и помещения, которых больше нет в выписке (обычно объединения);
   - изменение площади, номера, этажа;
   - новые и выбывшие собственники по каждому помещению;
   - изменение долей.
3. Администратор подтверждает изменения целиком или построчно.
4. При смене собственника:
   - баланс и история операций остаются за помещением;
   - прежний собственник отвязывается от помещения, и его пользователи теряют доступ к помещению;
   - новый собственник добавляется без учётной записи до загрузки контактов;
   - всё пишется в AuditLog.
5. Помещения, исчезнувшие из выписки, не удаляются автоматически: администратор оформляет объединение (п. 8.1) или разбирается вручную.

### 8.11 Раздел «Уведомления» (/admin/notifications)

#### Форма отправки
1. Получатели
   - «Все собственники» — неудалённые пользователи, привязанные к собственнику хотя бы одного помещения. Каждый получает одно уведомление.
   - «Выбрать вручную» — таблица с чекбоксами:
     - имя, телефон, помещения, язык, подписка;
     - фильтры: вид помещения, должники.
   - Счётчик выбранных и отдельно — сколько из них с подпиской.

2. Содержание
   - «Из объявления»: выбирается опубликованное объявление, заголовок и начало текста берутся из его переводов. Создаётся kind = ANNOUNCEMENT, отправляется всем выбранным.
   - «Произвольный текст» (kind = BROADCAST):
     - получатели группируются по языку;
     - для каждой группы — поля «Заголовок» и «Текст»;
     - необязательная ссылка.
   - Незаполненные языковые группы пропускаются (SKIPPED).
   - Рекомендуемая длина: заголовок до 50 символов, текст до 150. Предпросмотр.

3. Подтверждение и отправка
   - «Будет отправлено N уведомлений на M устройств. K получателей без подписки и L из незаполненных языковых групп уведомление не получат».
   - Отправка асинхронная, через очередь. Отображается прогресс.

#### История
- Таблица: дата, автор, вид (BROADCAST / ANNOUNCEMENT / BALANCE), получатели, статус.
- По умолчанию показываются BROADCAST и ANNOUNCEMENT. Уведомления BALANCE — через фильтр.
- В раскрываемой строке — статус по каждому получателю.

> Push-сервисы не подтверждают доставку на устройство. SENT означает, что сообщение принято push-сервисом.

### 8.12 Раздел «Собственники» (/admin/owners)
- Список собственников с пагинацией по 50 записей. Столбцы:
  - отображаемое и реестровое имя;
  - физлицо / юрлицо;
  - помещения с долями;
  - привязанная учётная запись (телефон) или «нет контакта».
- Поиск по имени (в обоих написаниях), номеру документа, номеру помещения, телефону.
- Фильтры: физлица / юрлица, без учётной записи, без помещений (бывшие собственники).
- Карточка собственника:
  - редактирование отображаемого имени, номеров документов, заметки;
  - список помещений и долей;
  - привязка учётной записи: выбрать существующую или создать новую (телефон, язык, временный пароль показывается один раз);
  - отвязка учётной записи.
- **Слияние дублей.** Если одно лицо оказалось в системе дважды, администратор выбирает основную запись. Права на помещения, номера документов и привязку учётной записи переносятся на неё, вторая запись удаляется. Операция пишется в AuditLog.
- Удаление собственника — только если у него нет помещений.

## 11. Безопасность

- Next.js middleware проверяет подпись JWT из cookie (общий секрет с бэкендом) и защищает только страницы:
  - `/{locale}/admin/*` без сессии ADMIN → редирект на `/{locale}/login`;
  - `/{locale}/account/*` без сессии → редирект на `/{locale}/login`.
- После входа пользователь возвращается на исходную страницу (`callbackUrl`, только относительные адреса).
- Окончательная проверка прав всегда выполняется на бэкенде, guard'ами NestJS на каждом эндпоинте:
  - роль;
  - `token_version`;
  - принадлежность помещения пользователю;
  - уровень доступа документа.
- Пароли хранятся как bcrypt-хэш (cost ≥ 12). Коды восстановления тоже хранятся только в виде хэша.
- CSRF-защита:
  - cookie `SameSite=Lax`;
  - проверка заголовка `Origin` на всех мутирующих запросах;
  - CORS не открывается: фронтенд и API на одном домене.
- Файлы хранятся в приватных бакетах MinIO. Скачивание — через presigned URL (TTL 1 час) после проверки доступа.
- Входные данные валидируются Zod-схемами на всех эндпоинтах.
- SQL-инъекции исключены использованием Prisma.
- Секреты (JWT, VAPID private key, ключи MinIO, SMS-провайдер) хранятся только в переменных окружения.
- Rate limiting: вход (п. 5.1) и восстановление пароля (п. 5.6).

## 12. Нефункциональные требования

- Мобильная адаптация: breakpoints xs/sm/md/lg (Tailwind).
- SEO: `<title>` и `<meta description>` на активном языке для каждой публичной страницы, `hreflang`, `<html lang>`.
- Кэширование:
  - страница услуг — ISR 60 сек;
  - объявления — revalidate 60 сек;
  - документы и личный кабинет — динамические.
  - Нагрузка небольшая, отдельный кэш не требуется.
- Доступность: базовый WCAG 2.1 AA.
- PWA: manifest, иконки, service worker с обработкой `push` и `notificationclick`.
- Логирование:
  - все административные и системные операции пишутся в AuditLog — начисления, оплаты, корректировки, входящие остатки, объединения, импорт, изменения пользователей, сброс паролей, документы, рассылки;
  - технические логи — в stdout контейнеров.
- Резервное копирование (сервис `backup` в Docker Compose):
  - ежедневно в 03:00: `pg_dump` + содержимое бакетов MinIO;
  - копии отправляются через `restic` в Backblaze B2 (S3-совместимое, дешёвое, другой провайдер и другая площадка, чем у сервера);
  - копии зашифрованы ключом restic. Ключ хранится вне сервера, у председателя и администратора;
  - хранятся 30 дневных и 12 месячных копий. Финансовые данные должны быть доступны за год;
  - ежедневно проверяется целостность (`restic check`). При ошибке бэкапа администраторам уходит push;
  - процедура восстановления описана и проверена до запуска.
  - При локальном тестировании бэкап пишется в локальную папку.
- Тесты:
  - обязательны для финансовой логики: расчёт начислений, паркинг, начисление новым помещениям, защита от дублей, объединение, импорт;
  - обязательны для проверок доступа: помещения, документы.

## 15. Голосования (предложение, требует утверждения)

> В версиях 1.0–1.2 голосований не было. Раздел описывает, как их можно реализовать. В объём работ он входит только после утверждения: юридическая сторона решается с юристом, вопросы — в п. 15.6.

### 15.1 Принципы
- **Одно действующее помещение — один голос:** квартиры, машиноместа, коммерческие и техническое помещение — всего 312 голосов. Объединённая квартира — один голос.
- Голос принадлежит помещению, а не человеку. Голосует пользователь помещения, то есть учётная запись, привязанная к одному из его собственников. Юрлицо голосует через представителя:
  - собственник двух квартир и машиноместа имеет 3 голоса;
  - у помещения с несколькими совладельцами — один голос.
- Список голосующих помещений фиксируется в момент открытия голосования. Последующие изменения помещений на него не влияют.
- Голоса можно подавать онлайн. Бумажные бюллетени вносит администратор с приложением скана.

### 15.2 Модель данных
```
Poll                — голосование
  id, title_ka/ru/en, description_ka/ru/en
  starts_at, ends_at
  status            Enum: DRAFT | OPEN | CLOSED | CANCELLED
  is_secret         Boolean — скрывать в результатах, кто как голосовал
  quorum_percent    Decimal (nullable) — порог явки для действительности
  created_by, created_at

PollQuestion        — вопрос голосования
  id, poll_id, text_ka/ru/en, sort_order
  threshold         Enum: SIMPLE_MAJORITY | QUALIFIED_2_3 | ... — порог принятия решения

PollOption          — вариант ответа (по умолчанию «За / Против / Воздержался»)
  id, question_id, text_ka/ru/en, sort_order

PollEligibleUnit    — снимок голосующих помещений
  poll_id, unit_id  PK (poll_id, unit_id)

Ballot              — голос помещения по вопросу
  id, question_id, unit_id, option_id
  user_id           — кто проголосовал (пользователь помещения) или NULL для бумажного
  owner_id          — от имени какого собственника подан голос
  source            Enum: ONLINE | PAPER
  entered_by        UUID → User (Admin, для PAPER)
  attachment_key    String (nullable) — скан бюллетеня
  created_at
  UNIQUE (question_id, unit_id)
```

### 15.3 Сценарий
1. Администратор создаёт голосование в статусе DRAFT: вопросы, варианты, сроки, кворум.
2. Открытие. В `starts_at` или вручную фиксируется список помещений, собственникам уходит push.
3. Голосование в личном кабинете. Пользователь видит свои помещения и отдельно голосует за каждое: «Квартира 45 — За», «Паркинг P-12 — Против».
4. За сутки до `ends_at` уходит push-напоминание тем, кто не проголосовал.
5. Закрытие в `ends_at` автоматически. Подсчёт:
   - по каждому варианту;
   - явка = число проголосовавших помещений / число голосующих помещений;
   - выполнение кворума и порога.
6. Протокол (PDF/XLSX) формируется автоматически. Администратор может опубликовать его в «Документах» в категории «Протоколы».

### 15.4 Страницы и API
- `/account/polls`, `/account/polls/:id` — голосование собственника.
- `/admin/polls`, `/admin/polls/new`, `/admin/polls/:id` — управление, внесение бумажных бюллетеней, результаты, протокол.
- API:
  - `GET /api/me/polls`;
  - `POST /api/me/polls/:id/ballots`;
  - `/api/polls/*` (ADMIN).

### 15.5 Безопасность
- Голосовать могут только пользователи помещений из снимка, связанные с текущими собственниками. Это проверяется на бэкенде.
- Собственники без учётной записи голосуют бумажным бюллетенем, который вносит администратор.
- Каждая подача и изменение голоса пишется в AuditLog.
- После закрытия голоса не изменяются.

### 15.6 Вопросы для утверждения
1. **Юридическая сила.** Признаётся ли онлайн-голосование по законодательству Грузии и уставу ТСЖ? Или это предварительный опрос, а решение принимается на собрании с бумажным протоколом? От ответа зависит, нужна ли усиленная идентификация (например, подтверждение голоса SMS-кодом). Рекомендуется консультация юриста.
2. **Совладельцы.** Кто голосует за помещение с несколькими собственниками? Варианты: только основной владелец, любой совладелец (засчитывается первый голос) или нужно согласие всех.
3. **Изменение голоса.** Можно ли изменить голос до закрытия голосования?
4. **Тайность.** Голосование тайное или поимённое? Видят ли собственники поимённые результаты?
5. **Кворум и пороги.** Какие нормы кворума и порогов принятия решений по уставу?
6. **Доверенности.** Голосование по доверенности: вносит ли администратор такой голос с приложением доверенности?
7. **Промежуточные результаты.** Видны ли они собственникам до закрытия?
8. **Должники.** Голосуют ли должники? По умолчанию — да, долг на право голоса не влияет.
